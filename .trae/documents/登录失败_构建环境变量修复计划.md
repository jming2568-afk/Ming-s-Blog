# 登录失败 & 构建环境变量修复计划

## 仓库调研结论

### 1. 登录报错根因（`Unexpected token '<', "<!DOCTYPE "... is not valid JSON`）
前端 [AuthContext.login](file:///workspace/components/AuthContext.jsx#L33-L45) 在 `fetch('/api/auth/login')` 后直接调用 `res.json()`，当 API 路由因任何原因崩溃时，Next.js 返回的是 HTML 错误页（`<!DOCTYPE html>...`），而非 JSON，导致解析失败并抛出此错误。用户看到的提示是错误信息的 `err.message`，但真实的服务端异常被吞掉了。

### 2. 潜在触发 API 崩溃的因素
- **better-sqlite3 原生模块问题**：虽然 [next.config.mjs](file:///workspace/next.config.mjs#L4) 已配置 `serverExternalPackages: ["better-sqlite3"]`，但 [lib/db.js](file:///workspace/lib/db.js#L14) 在模块加载时就同步实例化了数据库连接，并在 [login/route.js](file:///workspace/app/api/auth/login/route.js#L6-L7) 顶层调用了 `ensureTables()` 和 `ensureDefaultUsers()`。如果在构建时数据库路径写入权限缺失或 better-sqlite3 二进制不匹配，会在路由 handler 被调用前就直接抛异常，返回 500 HTML 页面。
- **缺乏错误响应兜底**：login/route.js 的 catch 虽然返回 JSON，但如果异常发生在模块加载阶段（`ensureTables()` 在 POST 之前），该 try/catch 完全覆盖不到。

### 3. 环境变量问题
- 项目根目录**没有任何 `.env*` 文件**。
- [lib/auth.js](file:///workspace/lib/auth.js#L5-L7) 中 `AUTH_SECRET` 使用了硬编码 fallback（`dev-fallback-secret-...`），构建时没有写入环境变量不会直接崩，但生产环境有安全隐患。
- 数据库路径 `process.cwd()/data/portfolio.db` 依赖运行时工作目录，构建产物部署时如果工作目录变化（例如 Vercel 只读文件系统），就会出现不可写或找不到库文件的问题。

### 4. 其他已发现问题（顺带修复）
- **Hydration mismatch**：日志显示 [MemphisDecor.jsx](file:///workspace/components/MemphisDecor.jsx) 生成随机装饰位置时，服务端与客户端的小数精度不一致（SSR 为 4 位，客户端为完整浮点数）。
- **`scroll-behavior: smooth` 警告**：`<html>` 缺少 `data-scroll-behavior="smooth"` 属性。
- **前端 fetch 未检查 Content-Type**：没有校验响应是 JSON 再解析，任何 404/500 HTML 页都会导致 JSON 解析错误并丢失真实错误信息。

## 修改步骤（按执行顺序）

### Step 1：新增 `.env.example` 模板
创建根目录 `.env.example`，包含：
```
# 用于 JWT 签名，生产部署必须设置（使用 `openssl rand -hex 32` 生成）
AUTH_SECRET=

# 可选：SQLite 数据库文件绝对路径，默认 <cwd>/data/portfolio.db
DB_PATH=

# 可选：上传文件存储目录，默认 <cwd>/public/uploads
UPLOAD_DIR=
```
不提交真实值，仅作模板。

### Step 2：修正数据库模块（lib/db.js）
1. 从 `process.env.DB_PATH` 读取覆盖默认路径。
2. 将 `ensureTables()`、`ensureDefaultUsers()`、`ensureSiteSettings()` 的顶层调用移除，改为导出一个 `ensureDb()` 幂等函数，内部用标志位控制只执行一次。
3. 模块顶层不再 `new Database(DB_PATH)`，改为懒加载：导出 `getDb()` 单例工厂，首次调用时创建连接并跑 ensureDb。
4. 在初始化失败时抛出自定义错误，消息中明确"better-sqlite3 二进制缺失/数据库路径不可写/AUTH_SECRET 缺失"等可能原因，便于定位。

### Step 3：修正 auth 模块（lib/auth.js）
- `AUTH_SECRET` 保留 fallback，但：
  - 当 `NODE_ENV === 'production'` 且 AUTH_SECRET 等于 fallback 时，**在 `createSession/verifySession` 被首次调用时抛出明确错误**，提醒生产环境必须设置。
  - 开发模式只打印一行 console.warn。
- 注释说明构建时需注入该环境变量。

### Step 4：修复所有 API 路由模块级副作用
对以下每个路由文件：
- 移除顶层的 `ensureTables()/ensureDefaultUsers()` 调用。
- 改为在 POST/GET handler 开头 `await getDb()` 或调用 `ensureDb()`（包一层 try/catch，失败返回 JSON 格式的 500）。
- `catch (err)` 中 `console.error` 输出完整 err.stack 并 `return NextResponse.json({ error: "...", debug: NODE_ENV!=='production' ? err.message : undefined }, { status: 500 })`。

### Step 5：修复前端 fetch 解析逻辑（AuthContext）
在 `login`、`refreshSession`、`logout` 中：
```js
const res = await fetch(...);
const ct = res.headers.get("content-type") || "";
if (!ct.includes("application/json")) {
  const text = await res.text();
  // 截取前 200 字，避免把整页 HTML 塞到 error 里
  const snippet = text.slice(0, 200).replace(/\s+/g, " ");
  throw new Error(`服务器返回非 JSON（status=${res.status}）：${snippet}`);
}
const data = await res.json();
```

### Step 6：修复 MemphisDecor hydration mismatch
定位随机数生成位置（MemphisDecor.jsx 中的种子随机函数），对所有输出的 `top/right/width/height/transform: rotate()` 数值统一 `.toFixed(4)`，保证 SSR 与客户端渲染结果逐字节一致。

### Step 7：修复 layout scroll-behavior 警告
在 [app/layout.js](file:///workspace/app/layout.js) 的 `<html>` 标签上添加 `data-scroll-behavior="smooth"` 属性。

### Step 8：scripts/init-db.js 对齐 DB_PATH
用 `process.env.DB_PATH || 路径` 与运行时逻辑一致，避免初始化脚本和运行时写到两个不同文件。

## 潜在依赖与注意事项

1. **better-sqlite3 原生绑定**：如果构建机和运行机架构不同（例如 x86 构建 → arm64 部署），better-sqlite3 需要在部署机器上单独 `npm rebuild better-sqlite3`。计划中不会自动处理跨架构问题，但会把错误信息变得可读，用户看到提示后可以自行重建。
2. **数据库文件系统写入权限**：Vercel serverless 环境不可写本地磁盘，部署到那里时此实现需要额外适配（例如改 Postgres/Turso）。本次不在计划范围内，但会在 `.env.example` 注释中标注。
3. **AUTH_SECRET 轮换**：切换 AUTH_SECRET 会让所有现有 Session Cookie 失效，修改后生产需确保重新登录。
4. **MemphisDecor 随机种子**：种子算法本身已确定，但格式化必须在**所有输出点**统一 toFixed(4)，否则仍会有零散 mismatch。

## 风险处理

| 风险 | 影响 | 缓解 |
|------|------|------|
| getDb 懒加载 + 每次 handler 内 ensureDb 调用性能 | 首次请求略变慢 | 使用 `let _db / let _ensured` 模块级标志位保证只跑一次初始化，后续 0 开销 |
| 生产缺失 AUTH_SECRET 时直接抛错，登录全挂 | 无法登录 | 在 `pnpm build` 或启动时做一次显式检查并打印醒目错误，不让问题带到运行中才暴露 |
| 格式化 MemphisDecor 时漏掉某个数值点 | hydration mismatch 残留 | 统一抽出 `fmt(n) => Number(n.toFixed(4))` 工具函数，所有数值经它输出 |
| 上传目录默认 `public/uploads` 与 .gitignore 冲突 | 运行时找不到目录 | upload route.js 启动时 `fs.mkdirSync(dir, { recursive: true })` 保证存在 |
