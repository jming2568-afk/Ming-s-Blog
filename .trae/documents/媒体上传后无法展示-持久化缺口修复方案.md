# 媒体上传后无法展示 — 持久化缺口修复方案

## Summary

用户在个人中心上传了头像 / 简历证件照 / 微信二维码后，设置页显示"✓ 已上传"，但简历页证件照框仍是空占位、联系页二维码不显示。根因是**持久化缺口**：`MediaUploader.onUploaded` 只更新本地 React state，真正落库需要单独点击"💾 保存个人资料"。用户未点保存（或未意识到要保存），DB 中 `cert_photo_url` / `wechat_qr_url` 为空，展示侧读取空值 → 走占位分支。

修复方案：**上传成功后立即按字段自动持久化到 DB**（复用现有支持局部更新的 `PUT /api/settings`），让"上传 = 保存 = 全站展示"一步到位，消除两步保存的认知负担。移除/更换同样自动持久化。

## Current State Analysis（决定性证据）

只读检查结果（curl `/api/settings` + 只读 SQLite SELECT）：

| 字段 | DB 当前值 | 含义 |
|---|---|---|
| `avatar_url` | `/uploads/2026/08/bfcffc5e-...png` | 上一轮用 curl 存的 1x1 测试图，**非**用户本轮上传的 88344a8e.jpg |
| `cert_photo_url` | `""`（空） | 用户上传了 f54b0b86.jpg 但**未落库** |
| `wechat_qr_url` | `""`（空） | 用户上传了 0e01027e.jpg 但**未落库** |

链路核查（均无问题，排除展示侧 bug）：
- 字段命名全链路一致：DB `cert_photo_url` → `getSiteSettings()` 返回 `certPhotoUrl` → API `settings.certPhotoUrl` → 消费端 `settings.certPhotoUrl`。无 mismatch。
- [ResumeTabs.jsx](file:///workspace/components/ResumeTabs.jsx) 客户端 `fetchSettings({ force: true })`（绕过 30s 缓存），`certPhotoUrl ? <img> : <占位div>`。用户选中的占位 div class `w-full h-full bg-white/25 border-[3px] border-dashed border-white/80` 与 else 分支逐字一致 → 运行时 `certPhotoUrl` 为 falsy → DB 为空。
- [app/contact/page.js](file:///workspace/app/contact/page.js) Server Component 服务端 `getSiteSettings()` 读 `wechatQrUrl`，`wechatQrUrl ? <img> : <占位>`。
- [NavBar.jsx](file:///workspace/components/NavBar.jsx) raw `fetch("/api/settings",{cache:"no-store"})` 读 `avatarUrl`，`site.avatarUrl ? <img> : <字母>`。
- [ProfileSettings.jsx](file:///workspace/components/ProfileSettings.jsx) `onUploaded={({ url }) => setCertPhotoUrl(url)}` **只改本地 state**；落库只在 `onSubmit`（点"保存个人资料"）时 `updateSettings({ avatarUrl, certPhotoUrl, wechatQrUrl, ... })`。
- [app/api/settings/route.js](file:///workspace/app/api/settings/route.js) PUT 支持局部更新：`for (k of keys) if (body[k] !== undefined) patch[k]=body[k]`，不同字段的并发 PUT 互不覆盖（各自只 SET 自己的列）。
- [lib/settings.js](file:///workspace/lib/settings.js) `updateSiteSettings` 只更新 `next` 中提供的列 + `updated_at`，空串也会写入（可用于清除）。

结论：**唯一根因 = 持久化缺口**。展示侧代码正确，DB 一旦有值即可正常渲染。

## Proposed Changes

仅改一个文件：[components/ProfileSettings.jsx](file:///workspace/components/ProfileSettings.jsx)

### 1. 新增 `persistMedia(field, url)` 辅助函数

在 `update` 函数附近新增（复用已 import 的 `updateSettings`）：

```jsx
const persistMedia = async (field, url) => {
  // field: "avatarUrl" | "certPhotoUrl" | "wechatQrUrl"
  const setter = {
    avatarUrl: setAvatarUrl,
    certPhotoUrl: setCertPhotoUrl,
    wechatQrUrl: setWechatQrUrl,
  }[field];
  const label = {
    avatarUrl: "个人头像",
    certPhotoUrl: "简历证件照",
    wechatQrUrl: "微信二维码",
  }[field];
  setter(url);          // 立即更新本地 state（UI 即时反馈）
  setMsg("");
  setError("");
  try {
    await updateSettings({ [field]: url });   // 局部持久化，复用现有 PUT
    setMsg(url
      ? `✅ ${label}已上传并保存，全站同步生效`
      : `✅ ${label}已移除并保存`);
  } catch (e) {
    setError(`已更新但保存失败：${e.message || "服务器错误"}（可点击底部"保存个人资料"重试）`);
  }
};
```

### 2. 三个 `MediaUploader` 的 `onUploaded` 改为调用 `persistMedia`

- 个人头像：`onUploaded={({ url }) => persistMedia("avatarUrl", url)}`
- 简历证件照：`onUploaded={({ url }) => persistMedia("certPhotoUrl", url)}`
- 微信二维码：`onUploaded={({ url }) => persistMedia("wechatQrUrl", url)}`

### 3. 保留底部"💾 保存个人资料"按钮（不变）

文字字段（displayName / bio / titles 等）仍走表单 `onSubmit` 批量保存。媒体上传器改为独立自动持久化，与文字保存互不干扰：`onSubmit` 仍会把当前 `avatarUrl/certPhotoUrl/wechatQrUrl` 一起带上（值已与 DB 一致，重复写无副作用）。

### 4. 覆盖"移除"场景（无需额外代码）

[MediaUploader.jsx](file:///workspace/components/MediaUploader.jsx) 的 `clear()` 已调用 `onUploaded?.({ url: "", type: "" })`，因此点"移除"会触发 `persistMedia(field, "")` → 本地清空 + `PUT {field: ""}` → DB 列置空 → 简历/联系页自动回退占位。上传 / 更换 / 移除三者一致自动持久化。

## Assumptions & Decisions

- **决策：采用"上传即保存"而非"强化两步保存提示"**。理由：用户已因两步流程受挫；现有"✓ 已上传"文案天然暗示已生效；局部 PUT 对不同字段并发安全；文字字段保留独立保存不冲突。这是直接对齐用户预期（"上传了就该能展示"）的最小改动。
- **不改动展示侧**（ResumeTabs / contact / NavBar）：经核查展示逻辑正确，DB 有值即可渲染，无需改。
- **不改动 MediaUploader**：上一轮已修复按钮遮挡问题，本轮 `clear()` 行为正好复用，无需再改。
- **并发安全**：`updateSiteSettings` 只 SET 提供的列，三个字段同时上传时各自 PUT 独立列，互不覆盖。
- **缓存**：ResumeTabs 用 `force:true`、NavBar 用 `no-store`、contact 服务端渲染——均无缓存阻碍，自动保存后导航到对应页即可看到。
- **失败处理**：PUT 失败时本地 state 已更新（设置页仍显示"已上传"），但提示"保存失败，可点底部保存重试"，不静默吞错。

## Verification Steps

1. 重启 dev server 确保新代码编译（`npm run dev -- -p 3000`）。
2. 浏览器登录 `useradmin / useradmin123` → /settings → 个人资料 tab。
3. **证件照**：上传一张图 → 等待"已上传并保存"提示 → 只读检查 `curl -s http://localhost:3000/api/settings` 确认 `certPhotoUrl` 非空。
4. 导航到 /resume → 右上角证件照框应显示 `<img>`（不再是虚线占位"证件照"）。用 `browser_evaluate` 确认该 div 内是 `<img src="/uploads/...">` 而非占位 div。
5. **微信二维码**：上传 → /contact 底部二维码区显示 `<img>` 而非"未设置微信二维码"占位。
6. **头像**：上传 → 刷新后 NavBar 右上角用户菜单按钮显示 `<img>` 而非字母。
7. **移除**：在设置页点证件照"移除" → `/api/settings` 的 `certPhotoUrl` 变 `""` → /resume 回到占位。
8. 回归：确认底部"保存个人资料"仍可正常保存文字字段，且不影响已自动保存的媒体值。
