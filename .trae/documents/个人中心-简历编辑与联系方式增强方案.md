# 个人中心 / 简历编辑 / 联系页增强 实现方案

## 一、需求摘要

1. **个人中心**：用户（useradmin）登录后进入独立页面，可修改：
   - 登录密码（需验证旧密码）
   - 个人头像（上传图片）
   - 展示名称（全站同步生效）
   - 其他个人资料：邮箱、GitHub 昵称/链接、意向城市、微信号、微信二维码、个人简介、头衔列表、简历证件照
2. **简历内容编辑**：以**结构化表单**方式编辑双版本简历（aigc / dev）的全部内容（结构化表单），并支持**展示媒体**（证件照）。
3. **简历右上角证件照区域**：在简历页右上角放置一个约「两寸」的方形照片框，展示用户证件照（可空占位）。
4. **联系页增强**：新增「微信号」展示栏 + 底部「微信二维码」展示区域；联系方式信息与跳转链接全部可编辑（全站同步）。

- 技术栈：Next.js 16.2.6 App Router、React 19、Tailwind v4、SQLite（better-sqlite3）、JWT session cookie（jose）、bcryptjs。

  - 静态模块 [data/profile.js](file:///workspace/data/profile.js)：name / titles / location / email / github / githubUrl / avatar / bioShort / bioLong / highlights。
  - 静态模块 [data/resume.js](file:///workspace/data/resume.js)：`resumeVersions = { aigc, dev }`，两版结构不同：
    - 公共：`title`、`summary`、`workExperience[]`（company/period/role/points[]）、`education[]`（period/school/desc）、`certs`。
    - aigc 独有：`works[]`（name/role/result）、`abilities[]`（item/desc）。
    - dev 独有：`projects[]`（name/role/points[]）、`techStack[]`（cat/items）。
  - SQLite [lib/db.js](file:///workspace/lib/db.js)：`users` / `projects` / `login_failures` 表；`ensureTables()` 在 API 导入时执行。
- 认证：`app/api/auth/login|logout|session`；登录惩罚已实现；`getCurrentUser()` 读取 session。
- 上传：[app/api/upload/route.js](file:///workspace/app/api/upload/route.js) 写入本地 `public/uploads/YYYY/MM`，[MediaUploader.jsx](file:///workspace/components/MediaUploader.jsx) 提供拖拽/进度/预览（本地文件系统上传在本沙箱可用）。
- 公开资料展示点（当前均读取静态 `data/profile.js` / `data/resume.js`）：
  - NavBar（客户端）品牌名「李佳铭 + SubMing.Top」、登录头像（字母）。
  - HeroSection（客户端）姓名/头衔/简介。
  - Contact（服务端）邮箱/GitHub/城市。
  - Footer（服务端）姓名/简介/头衔/邮箱/GitHub。
  - ResumeTabs（客户端）静态 `resumeVersions`。
- 已有可复用 UI：`UiInput`（支持 textarea）、`UiButton`、`UiTag`、`MediaUploader`、`SectionTitle`、`MemphisDecor`。
- 登录用户菜单：NavBar → 管理作品(/portfolio) / 退出登录（[NavBar.jsx](file:///workspace/components/NavBar.jsx#L158-L177)）。

## 三、方案设计（Proposed Changes）

### 数据层：新增 `site_settings` 单行表（SQLite）

**修改 [lib/db.js](file:///workspace/lib/db.js)**

在 `ensureTables()` 的 `db.exec` 中追加：

```sql
CREATE TABLE IF NOT EXISTS site_settings (
  id INTEGER PRIMARY KEY CHECK (id = 1),
  display_name TEXT NOT NULL DEFAULT '',
  avatar_url TEXT NOT NULL DEFAULT '',
  cert_photo_url TEXT NOT NULL DEFAULT '',
  email TEXT NOT NULL DEFAULT '',
  github TEXT NOT NULL DEFAULT '',
  github_url TEXT NOT NULL DEFAULT '',
  location TEXT NOT NULL DEFAULT '',
  wechat_id TEXT NOT NULL DEFAULT '',
  wechat_qr_url TEXT NOT NULL DEFAULT '',
  bio_short TEXT NOT NULL DEFAULT '',
  bio_long TEXT NOT NULL DEFAULT '',
  titles_json TEXT NOT NULL DEFAULT '[]',
  resume_json TEXT NOT NULL DEFAULT '{}',
  updated_at INTEGER NOT NULL DEFAULT (strftime('%s','now'))
);
```

在 `ensureDefaultUsers()` 同级新增 `ensureSiteSettings()`：若 `id=1` 行不存在，则用 `data/profile.js` 的默认值 + `data/resume.js` 的 `resumeVersions`（JSON.stringify）插入默认行（幂等）。

**修改 [data/profile.js](file:///workspace/data/profile.js)**：追加两个默认字段（值为空字符串）：`wechatId: ""`、`wechatQrUrl: ""`，作为联系方式默认值。`data/resume.js` 保持不变（作为简历默认值）。

### 服务端数据访问层：新增 [lib/settings.js](file:///workspace/lib/settings.js)

导出（Node 服务端专用，同步 better-sqlite3）：

- `getSiteSettings()`：读取 `site_settings` 行，合并静态默认值，返回公开字段对象：
  `{ displayName, avatarUrl, certPhotoUrl, email, github, githubUrl, location, wechatId, wechatQrUrl, bioShort, bioLong, titles: string[], updatedAt }`
  （空字段回退到 `data/profile.js` 默认值；`displayName` 为空回退 "李佳铭"）。
- `getResumeData()`：解析 `resume_json`，校验结构合法则返回，否则返回 `data/resume.js` 默认 `resumeVersions`。
- `updateSiteSettings(patch)`：白名单字段逐一 sanitize（字符串、titles 数组转 JSON），更新 `updated_at`。
- `updateResumeData(resume)`：先 `validateResume(resume)`，通过后存 JSON。
- `validateResume(resume)`：必须存在 `aigc`、`dev` 两个版本，且每版含 `title`/`summary`/`workExperience`/`education`/`certs`；aigc 含 `works` 或 `abilities`、dev 含 `projects` 或 `techStack`（宽松校验，缺少则报错）。

### API 路由（新增 3 个）

1. **`app/api/settings/route.js`**
   - `GET`（公开）：返回 `{ ok, settings: getSiteSettings(), resume: getResumeData() }`。
   - `PUT`（需登录）：接收 `{ displayName?, avatarUrl?, certPhotoUrl?, email?, github?, githubUrl?, location?, wechatId?, wechatQrUrl?, bioShort?, bioLong?, titles?: string[] }`，白名单更新。
2. **`app/api/settings/password/route.js`**
   - `PUT`（需登录）：body `{ oldPassword, newPassword }`；校验 `newPassword.length >= 6 && <= 72`；`bcrypt.compare(oldPassword, user.password_hash)` 失败返回 400「原密码错误」；通过后 `hashPassword(newPassword)` 更新 `users.password_hash`，返回 `{ ok: true }`。
3. **`app/api/settings/resume/route.js`**
   - `PUT`（需登录）：body `{ resume }`；`validateResume` → `updateResumeData`，返回 `{ ok, resume }`。

> 注：三个 PUT 均先 `await getCurrentUser()`，未登录返回 401（复用现有逻辑）。GET 公开供全站前端拉取。

### 客户端数据访问：新增 [lib/settingsStore.js](file:///workspace/lib/settingsStore.js)

仿照 [lib/projectsStore.js](file:///workspace/lib/projectsStore.js)：

- `fetchSettings({ force })`：GET `/api/settings`，返回 `{ settings, resume }`，30s 内存缓存。
- `updateSettings(payload)`：PUT `/api/settings`，成功后清缓存。
- `changePassword(oldPassword, newPassword)`：PUT `/api/settings/password`。
- `saveResume(resume)`：PUT `/api/settings/resume`，成功后清缓存。
- `invalidateSettingsCache()`。

## 四、决策与假设（Assumptions & Decisions）

1. **存储**：个人资料 + 简历统一存 SQLite `site_settings` 单行；静态 `data/profile.js` / `data/resume.js` 仅作为默认值（首次 seed / 空字段回退）。不引入新依赖。
2. **全站同步**：Hero（客户端 fetch）、Contact/Footer（服务端直接读库）、NavBar（客户端 fetch）、ResumeTabs（客户端 fetch）全部接入动态数据；`metadata` 标题与首页 `highlights` 保持静态（需求未要求）。
3. **「展示媒体」范围**：简历的展示媒体 = 右上角证件照（certPhotoUrl），在个人中心「个人资料」面板上传；不做简历内嵌作品媒体墙（超出本次需求）。
4. **密码规则**：新密码长度 6–72（bcrypt 上限），需原密码校验；改密码接口不触发登录失败惩罚（已登录操作）。
5. **权限**：所有写操作需登录（GET `/api/settings` 公开）；沿用现有 `getCurrentUser()` 与 401 约定。
6. **微信二维码/微信号**：默认空字符串；上传复用 `/api/upload`（本地文件系统，沙箱内可用）。
7. **登录入口**：个人中心为独立页面 `/settings`，从 NavBar 用户菜单进入；未登录访问显示引导而非整页重定向（避免打断浏览）。
8. **结构化表单**：列表类字段采用「列表项添加/删除 + 文本框/textarea」；`points` 类多行用「一行一条」textarea 简化输入（保存时分行转数组），避免过重 UI。
