# 个人资料「上传图片后按钮被图片遮罩覆盖」修复方案

## 一、需求摘要

用户反馈：在 `/settings` 个人中心「个人资料」面板上传图片后，「上传到服务器」「保存个人资料」按钮无法点击，疑似被上传图片的遮罩覆盖。要求优化个人资料编辑部分的图片上传体验，确保上传后按钮始终可点、可换图、可保存。

## 二、现状分析（已探索）

### 问题组件
- [components/MediaUploader.jsx](file:///workspace/components/MediaUploader.jsx)（共享上传组件，`ProfileSettings` 与 `ProjectEditor` 都用）：
  - 预览分支（[L182-L248](file:///workspace/components/MediaUploader.jsx#L182-L248)）：容器 `relative ... overflow-hidden`，图片在 `w-full aspect-video` + `object-cover` 内全幅裁切展示；下方 `p-4` 面板放「⬆ 上传到服务器」按钮。
  - 空态 dropzone（[L127-L181](file:///workspace/components/MediaUploader.jsx#L127-L181)）内含隐藏 `input[type=file]`；**预览态没有文件输入框**，意味着已有图片时只能先点「✕ 移除」再重新选择，无法直接更换。
- [components/ProfileSettings.jsx](file:///workspace/components/ProfileSettings.jsx#L119-L162)：3 个上传组件挤在 `grid grid-cols-1 sm:grid-cols-3` 里，证件照/二维码是竖图/方形，窄列下 16:9 裁切 + 按钮面板易造成视觉拥挤。
- [app/globals.css](file:///workspace/app/globals.css#L43-L121)：`shadow-memphis`（4px 硬阴影）、`bg-mem-grid` 网格背景，均为纯背景无绝对定位覆盖。

### 排查结论（关键）
- 用浏览器在**桌面视口**与**模拟 ~420px 移动单列**下，用 1x1 与 600x900 竖版 PNG 模拟选图后检查：
  - 预览 img：`top/bottom` 与按钮矩形无相交（图片 bottom 1085 恰好紧贴面板 top，按钮 top 1136，间隔 51px）；
  - 「上传到服务器」「保存个人资料」按钮中心 `document.elementFromPoint` 均命中按钮自身；
  - 上传按钮 `position:static、z-index:auto`，预览容器 `aspect-ratio:16/9` 计算值生效、`overflow:hidden` 生效。
- 即：**当前源码在常规渲染下并不存在几何遮挡**。用户所见问题大概率来自特定视口/构建/缓存下的渲染不确定性，例如：
  1. `aspect-video` 或 `object-cover` 类在用户构建中未生效 → 预览容器失去固定高度，图片按原始比例撑开，视觉上「盖住」下方内容（虽然 `overflow-hidden` 会裁剪，但不同构建/浏览器下表现不一）；
  2. 窄列 3 宫格 + 16:9 全幅裁切 → 竖版证件照被裁掉主体、二维码被裁，加上硬阴影，视觉上像被图「遮罩」；
  3. 用户浏览器加载了改动前的旧缓存 JS/CSS。

> 计划目标：**从源码层面消除该症状的一切可能**，并顺带优化上传体验（可点击预览直接更换、按钮层级与指针明确、布局更清晰），对共享组件 `MediaUploader` 的修改同时惠及作品集上传。

## 三、方案设计（Proposed Changes）

### 1. 改造 [components/MediaUploader.jsx](file:///workspace/components/MediaUploader.jsx)（根因防护）

1. **预览容器改为「显式固定高度 + 居中 + 完全裁切」**，不再依赖 `aspect-video`/`object-cover`：
   - 图片/视频外层：`relative w-full h-44 sm:h-52 overflow-hidden bg-mem-grid flex items-center justify-center`
   - 图片：`max-h-full max-w-full object-contain`（竖版证件照/方形二维码完整可见，不裁不撑）
   - 视频：`max-h-full w-full object-contain bg-mem-black`
   - 效果：无论构建里 `aspect-video` 是否生效、图片原始比例如何，预览高度恒为 176/208px，**从几何上不可能盖住下方按钮**。
2. **按钮与面板层级/指针明确**：
   - 上传面板 `p-4 ...` 增加 `relative z-[1]`；
   - 图片/视频容器增加 `pointer-events-none`（媒体不拦截任何点击）；
   - 预览容器根节点增加 `isolate`；「✕ 移除」按钮 `z-20`。
3. **支持「点击预览直接更换图片」**（修复已有图片时无法直接重选的痛点）：
   - 把隐藏 `input[type=file]` 从空态分支**上移到组件根节点**（`<div className="w-full space-y-3">` 内），两个分支共用同一个 input；
   - 预览容器加 `onClick={() => inputRef.current?.click()}` + `cursor-pointer` + 右下角小提示「点击更换」；
   - 空态 dropzone 保持原点击行为。
4. 其余（上传进度、`已上传` 状态栏、`doUpload/clear` 逻辑）保持不变，最小改动。

### 2. 优化 [components/ProfileSettings.jsx](file:///workspace/components/ProfileSettings.jsx) 媒体区布局

1. 媒体区网格由 `grid-cols-1 sm:grid-cols-3` 改为 `grid grid-cols-1 md:grid-cols-3 gap-6 items-start`（小屏单列、中屏三列但顶部对齐），避免窄列挤压；
2. 每个上传器外层 `<div>` 加 `min-w-0`，标签下补一行小字说明（头像→导航栏、证件照→简历右上角、二维码→联系页底部），明确用途；
3. 在媒体区底部提示语中补充：「选择图片后可先预览再上传；点击预览图可直接更换」。
4. 「保存个人资料」按钮保持 `type="submit"` 位于表单末尾，配合第 1 点的高度约束，滚动到页底即可点击。

### 3.（无需改动）说明
- `ProjectEditor.jsx` 复用 `MediaUploader`，自动获得固定高度预览与点击更换能力；其视频上传场景由 `object-contain + 固定高` 兼容（视频完整可见）。
- 不修改 `/api/upload`、`lib/settings.js` 等后端逻辑（与本次问题无关）。

## 四、决策与假设（Assumptions & Decisions）

1. **根因不可在本环境复现**：源码当前布局在桌面/移动视口均无几何遮挡；本方案以「消除一切可能的渲染不确定性」为目标（固定高度 + 居中 + overflow 裁剪 + 层级/指针明确），而非仅修一个像素级 bug。
2. **预览改为 `object-contain`**（完整显示整张图），替代 `object-cover`（全幅裁切）。对证件照/二维码是明显改进（不再裁掉主体）；对作品集封面会略留边，属可接受取舍。
3. **布局改为 `items-start` 三列 + 单列兜底**：保持视觉紧凑同时避免挤压；不改 `sm:grid-cols-3` 断点语义以外的结构。
4. **不引入新依赖**，不改后端，改动聚焦 `MediaUploader`（共享）与 `ProfileSettings`（个人页）。

## 五、验证步骤（Verification）

1. 重启 dev server（如运行中则 Turbopack 热更），硬刷新 `/settings?tab=profile`（Ctrl+Shift+R），确认无编译错误。
2. **浏览器验证（选图后不点真实上传，只做布局检查）**：
   - 在三个上传器分别注入 600x900 竖版 PNG 与 1x1 PNG，检查预览 img 的 `getBoundingClientRect().height ≤ 208px`，且与「上传到服务器」「保存个人资料」按钮矩形不相交；
   - 两按钮中心 `elementFromPoint` 命中按钮自身；
   - 预览图点击后能再次打开文件选择（存在可复用的隐藏 input）。
3. **真实上传验证**：登录后对「简历证件照」真实上传一张竖版图片（POST /api/upload → 本地 uploads），确认预览显示完整竖图、「已上传」状态正常、可点「✕」移除、可点预览更换；再对「微信二维码」上传并到 `/contact` 确认二维码区显示图片。
4. **页面回归**：`/settings` 三个 Tab 正常；`/portfolio` 作品管理上传（MediaUploader 复用）视频/封面预览正常、按钮可点；登录失败惩罚、简历页证件照框不受影响。
