# 开发阶段规划（P1–P6）

> 依据：PRD-001（产品需求）。每个阶段结束设**确认点**：验收通过才进入下一阶段，可随时压缩/裁剪范围。
> 进度：见文末「进度跟踪」表，随阶段推进更新。
> **部署架构：以 TECH-001（低内存原生部署·方案 A）为准**，替代原 Docker Compose 口径（2026-08-15 起）。

---

## 一、阶段总览

| 阶段 | 名称 | 核心内容 | 预计工作量（单人+AI） |
|---|---|---|---|
| **P1** | 骨架与基础设施 | monorepo 初始化（web/api/shared/ui 空壳）、docker-compose（nginx+api+postgres）、多阶段 Dockerfile、CI、`/api/health` 跑通 | 0.5–1 周 |
| **P2** | 认证与用户 | users/sessions 表 + 注册/登录/登出（httpOnly cookie）+ 路由守卫 + 限流 | 0.5–1 周 |
| **P3** | 简历核心（最大） | 简历 CRUD + 编辑器（分栏/自动保存/校验）+ 5 套主题 + 公共分享页 `/r/:slug` + **`@media print` A4 打印**（一致性内核第一步） | 1.5–2.5 周 |
| **P4** | 交付与媒体 | PDF 导出（客户端打印，见 TECH-001）、Word 导出（docx）、二维码、头像/证书上传（阿里云 OSS 接入） | 1–1.5 周 |
| **P5** | AI 能力与平台侧 | AI 写作助手、AI 旧简历导入（OCR+LLM 提取）、admin 管理端、安全加固 | 1–2 周 |
| **P6** | 上线与试运行 | VPS（2C1G 低内存）原生部署（systemd + 宿主机 nginx）、域名/HTTPS、OSS 生产配置、SQLite 备份、监控、20 人内测（详见 TECH-001） | 0.5–1 周 |

**合计约 5–9 周**。P1–P3 是「必须」主线；P4–P5 是增强；P6 上线。

---

## 二、各阶段验收标准（决定是否进入下一阶段）

| 阶段 | 验收 |
|---|---|
| **P1** | `docker compose up` 后三服务起来；`/api/health` 返回 200；web 构建通过；CI 绿（**P1 时点的 Docker 验收记录**；生产部署口径已改为原生 systemd + nginx，见 TECH-001） |
| **P2** | 注册 → 登录 → 登出全流程；未登录访问 `/app/*` 重定向 `/login` |
| **P3** | 编辑 → 发布 → 专属链接 → 手机打开 → **打印版式与线上一致**（硬指标） |
| **P4** | 打印/另存 PDF 与展示页同版式（客户端 `window.print()`，TECH-001 §4.2）；docx 可打开编辑；二维码扫码即开；头像上传成功（S3 兼容：MinIO 验证 / 生产 OSS） |
| **P5** | 上传扫描件 10 秒内生成可编辑草稿（LLM 配 key 后验收）；AI 润色可用；admin 可查用户/简历（ADMIN_USERNAMES） |
| **P6** | 线上可注册、可编辑、可分享、可打印；数据有备份；无高危安全项 |

---

## 三、关键安排

1. **一致性内核从 P3 第一天进验收**——打印样式不是后补功能，是产品灵魂（PRD-001 第 8 节）。
2. **PDF 生成改为客户端浏览器打印**（`window.print()` + `@media print`，复用 P3 一致性内核）；原 Playwright/Chromium 服务因低内存 VPS 已取消（见 TECH-001 §4.2）。
3. **VPS 已采购**：阿里云经济型 `ecs.e-c2m1.large`（2C1G，可用 ~700MB，暂无法升级，见 TECH-001）；OSS 桶在 P4 接入时创建。
4. **阶段结束给确认点**：验收通过才进下一阶段；随时可要求压缩范围（如 P5 admin 先不做）。

## 四、可拆分的粒度

- P3 可拆：3a 编辑器 / 3b 主题 / 3c 分享页+打印
- P5 可拆：5a 写作助手 / 5b 导入 / 5c admin
- 默认按 6 阶段走；需要拆随时调整本文件（状态保持 active，更新 updated 字段并 `pnpm docs:index`）。
