# 部署与更新手册（原生部署版）

> 配套：TECH-001（低内存原生部署·方案 A）。
> **更新机制定案（2026-08-15）**：本地构建 → 构建产物（dist）经 **scp/tar 直传**服务器 → 数据库迁移 → `systemctl restart`。
> 目标环境：阿里云首尔地域 2C1G VPS（可用 ~700MB + 4G swap），Debian 12，nginx + Node 22 + systemd。

---

## 0. 核心思想

- **构建只在开发机/CI 上做，不落在服务器上**：Vite/tsup 构建峰值 1–2GB 发生在开发机或 CI runner，服务器只接收**构建产物**，内存只伺候生产进程（当前空闲常驻 ~170–200MB）。
- **传产物，不传源码**：服务器无源码、无 git、无 Docker、无构建工具；更新 = 同步产物 + 迁移 + 重启。
- **传输用两端原生工具**：本机 Windows 自带 `C:\Windows\System32\OpenSSH\scp.exe` 与 `tar.exe`；服务器 Debian 自带 `/usr/bin/scp` 与 `tar`。复用 `ssh shouer` 密钥连接，**无需安装 rsync / git / Docker / ossutil 传输工具**。
- **CI 是验证门禁**：push 后 GitHub Actions 跑 typecheck/test/build，全绿才部署；CI 不自动部署（可选增强，暂不做）。

## 1. 服务器目录布局（/opt/resume-platform）

```
/opt/resume-platform/
├── app/
│   ├── web/                  # SPA 静态产物（nginx 根目录）
│   └── api/                  # API 构建产物（node dist/index.js）
├── data/
│   └── resume.db             # SQLite（WAL 模式）
├── logs/
│   └── api.log               # systemd journal 或 stdout 重定向
├── backups/                  # SQLite 备份 + 发布前产物备份
└── releases/                 # （可选增强）版本化发布目录 + current 软链
```

## 2. 首次部署（从零）

1. 建目录：`mkdir -p /opt/resume-platform/{app/{web,api},data,logs,backups}`
2. 写入 systemd unit `resume-api.service`（见 deploy/resume-api.service）：
   - `ExecStart=/usr/bin/node dist/index.cjs`、`WorkingDirectory=/opt/resume-platform/app/api`
   - `Environment=SQLITE_PATH=/opt/resume-platform/data/resume.db` 及引导变量
   - `Restart=always`、可选 `MemoryMax=512M`
3. 写入 nginx 站点配置（见 deploy/nginx-resume.conf）：`/` → SPA 静态；`/assets/*` 长缓存；`/api/*` → 反代 127.0.0.1:3000；`nginx -t && systemctl reload nginx`
4. 首次传输产物（deploy.sh 或手动 scp/tar）→ `systemctl start resume-api`
5. 首次启动自动执行 drizzle 迁移（`runMigrations()` 幂等）→ 验证 `/api/health` 200

### 引导环境变量（.env 只需这几项，其余进管理面板）

```env
SQLITE_PATH=/opt/resume-platform/data/resume.db
CONFIG_MASTER_KEY=<openssl rand -hex 32>   # 配置加密主密钥（AES-256-GCM），务必保密，丢失后已加密的密钥项无法解密
PORT=3000
NODE_ENV=production
# ADMIN_USERNAMES=ming   # 可选：首次引导管理员（之后可在面板维护）
```

> **配置中心**：LLM 密钥/模型/协议、OSS 凭证/桶等均改为**管理面板**（`/admin` → 平台控制面板）实时配置，存库且敏感值用 `CONFIG_MASTER_KEY` 加密（`enc:v1:` 格式）。面板保存立即生效，无需重启；密钥不回显。详见 TECH-001/相关文档。

## 3. 日常更新流程（主推：本地构建 + 直传）

```
① 本地 git 切 v0.3、拉最新
② 校验（推荐先推后建）：push → GitHub Actions 全绿后再部署；或本地 pnpm typecheck + pnpm test
③ 本地构建：pnpm --filter @platform/web build && pnpm --filter @platform/api build
④ 运行 deploy/deploy.sh（幂等，≤2 分钟）：
   备份服务器上一版（web.prev / api.prev）+ SQLite 备份
   tar 管道（或 scp -r）传输：web 传 dist；api 传 dist + package.json
   远程：npm install --omit=dev（装 better-sqlite3 等原生模块的 Linux 版）→ 重启（启动时自动迁移）
   健康检查 curl http://127.0.0.1:3000/api/health
⑤ 异常回滚：--rollback 还原上一版 + SQLite 备份 → 重启（秒级）
```

### 3.1 传输方式（两端原生，二选一）

- **推荐：tar-over-ssh 管道**（压缩 + 整目录替换，删掉旧文件）：
  ```bash
  tar -C apps/web -czf - dist | ssh shouer "rm -rf /opt/resume-platform/app/web && mkdir -p /opt/resume-platform/app/web && tar -xzf - -C /opt/resume-platform/app/web"
  tar -C apps/api -czf - dist package.json | ssh shouer "rm -rf /opt/resume-platform/app/api && mkdir -p /opt/resume-platform/app/api && tar -xzf - -C /opt/resume-platform/app/api"
  ssh shouer "cd /opt/resume-platform/app/api && npm install --omit=dev --no-audit --no-fund"   # better-sqlite3 原生模块须在 Linux 上安装
  ```
- **备用：scp -r**（无需管道，Windows 原生 scp.exe）：
  ```bash
  ssh shouer "rm -rf /opt/resume-platform/app/web && mkdir -p /opt/resume-platform/app/web"
  scp -r apps/web/dist/* shouer:/opt/resume-platform/app/web/
  ```

### 3.2 deploy.sh 说明（platform/deploy/deploy.sh）

- 步骤：① 校验本地 Node 版本（≥22，见 .nvmrc）→ ② 本地构建 → ③ ssh 备份服务器上一版 + SQLite → ④ tar 管道传输 web 静态 + api（dist+package.json）→ ⑤ 服务器端 `npm install --omit=dev`（**better-sqlite3 原生模块在 Linux 上安装/编译**）→ ⑥ 重启（启动自动迁移）+ 健康检查
- **为什么服务器端要 npm install**：better-sqlite3 是原生模块，Windows 构建的二进制与 Linux 不兼容，必须在服务器上安装/编译（已确认服务器可访问 GitHub 拉 prebuilt，且 gcc/make/python3 齐全可源码编译兜底）
- 回滚：`deploy.sh --rollback` 恢复 `backups/web.prev`、`api.prev` 与 SQLite 备份后重启
- 幂等：重复执行安全；失败即停，不半途而废

## 4. 前端/后端更新的区别

| 端 | 更新方式 | 停机 |
|---|---|---|
| 前端 SPA（静态） | tar/scp 覆盖 dist，新 index.html + hash 资源 | **零停机**，用户下次打开即新版 |
| 后端 API | 传产物 → 迁移 → 重启 systemd 服务 | 1–2s 抖动（Hono 启动快） |

- 顺序建议：先同步前端（零停机），再重启 API。
- 静态资源长缓存 `/assets/*`（immutable）依赖文件名 hash，覆盖即淘汰旧版本，无需清缓存。

## 5. 数据库迁移（SQLite）与备份

- **迁移方式**：drizzle-kit 生成 SQLite 迁移 → 部署时执行（API 启动自动跑，或显式 `migrate-cli.js`）。
- **铁律：迁移前必须备份**：
  ```bash
  sqlite3 /opt/resume-platform/data/resume.db ".backup /opt/resume-platform/backups/pre-migrate-$(date +%F).db"
  ```
- **每日备份 cron**（backup.sh）：`30 3 * * * /opt/resume-platform/backup.sh`（sqlite .backup + ossutil cp 到 OSS 媒体桶）
- SQLite 并发写：WAL + busy_timeout（已在代码层设置）；20 人规模无需额外锁。
- 迁移是增量的（ADD COLUMN 等）；不可逆操作前人工 review 生成的 SQL。

## 6. 回滚方案（等价于 Docker 镜像回滚）

### 6.1 代码/产物回滚（两层保险）

| 级别 | 做法 | 耗时 |
|---|---|---|
| L1 产物级 | `deploy.sh --rollback`：恢复 `backups/web.prev / api.prev` → 重启 | 秒级 |
| L2 版本级（增强） | `releases/<ver>/` + `current` 软链，systemd 指向 `current` | 秒级，可保留多版本 |
| L3 代码级 | `git checkout <上一tag>` → 重新构建 → 直传发布 | 分钟级 |

### 6.2 数据回滚
- 迁移失败/数据异常 → 用 `backups/pre-migrate-*.db` 还原：停服务 → 覆盖 resume.db → 启动。

## 7. 无 Docker 缺失项的弥补对照

| Docker 提供的能力 | 原生部署的替代 | 状态 |
|---|---|---|
| 镜像版本管理 | 本地 git tag + 服务器 releases/软链（或 dist.prev 备份） | 建议 P6 落地 |
| 环境可复现 | `.nvmrc` 锁 Node 22 + `pnpm-lock.yaml` frozen install + 部署脚本 | 已约定 |
| 隔离/安全 | systemd（Restart=always、可选 MemoryMax、NoNewPrivileges）+ ufw/fail2ban | 落地清单项 |
| 一键编排/分发 | deploy.sh 幂等脚本（本地构建 + scp/tar 直传） | 本次交付 |

## 8. 运维日常

- **健康检查**：`curl http://127.0.0.1:3000/api/health`（或 nginx 外网探测），cron 每 5 分钟，失败告警。
- **日志**：`journalctl -u resume-api -f`；logrotate 或 journald 自带轮转。
- **内存观测**：`free -m` 常态 < 250MB；swap 有使用说明存在压力，排查泄漏。
- **安全**：ufw 只放 22/80/443；fail2ban 保持启用。

---

## 9. 故障恢复 checklist

1. API 起不来 → `journalctl -u resume-api -n 50`；检查 `SQLITE_PATH`/环境变量/迁移是否失败。
2. 发布后 500 → 先 `deploy.sh --rollback`（L1/L2），再排查代码。
3. 迁移报错 → 用 pre-migrate 备份还原，重新生成迁移 SQL review 后再发。
4. 磁盘满 → `df -h`；清理 backups 旧文件、apt 缓存。
5. 内存打满 → `free -m` + `ps aux --sort=-%mem | head`；必要时重启服务释放。

## 10. 移交 coder 的产物约定（勿改动）

- 产物路径：`apps/web/dist` → `/opt/resume-platform/app/web/dist`（nginx root 指向 `app/web/dist`，deploy.sh 的 tar 保留 `dist/` 层级）；`apps/api/dist` + `apps/api/package.json` → `/opt/resume-platform/app/api`（部署时服务器执行 `npm install --omit=dev` 装原生模块；systemd `WorkingDirectory=/opt/resume-platform/app/api`，`ExecStart=node dist/index.cjs` 即 `app/api/dist/index.cjs`）
- API 启动时自动迁移（幂等）保留；环境变量名固定为 `SQLITE_PATH`
- 本地与 CI 用同一 Node 版本（.nvmrc 锁 22）
